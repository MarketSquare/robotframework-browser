# dynamic-test-app

Express-based HTTP/HTTPS server that provides static test pages and a logging
API for the Robot Framework Browser library acceptance tests.

## Architecture

```
node/dynamic-test-app/
├── src/
│   ├── server.ts          # Express server entry point
│   └── http-test.ts       # Generic echo/respond/basic-auth endpoints for http.html
├── static/                # Served at /  (express.static)
│   ├── *.html             # Test pages
│   ├── http.html, http.js # Generic HTTP test page
│   ├── http-fixtures/     # Binary fixtures for uploads and /api/respond?file=
│   ├── frames/            # Frameset/iframe pages
│   └── test-app-logger.js # Client-side event capture (injected into every page)
└── dist/
    └── server.js          # Compiled output (generated by `inv create-test-app`)
```

## Logging

All log output is written as newline-delimited JSON to **stdout**.  The test
runner captures this per-process into:

```
atest/output/test-app/test-app-<port>.log
```

### Log entry schema

Every entry has a `timestamp` field (ISO 8601 UTC) plus an `event` field that
identifies the entry type.

#### Server events

Written directly by `src/server.ts`.

| `event`        | Additional fields |
|----------------|-------------------|
| `server_start` | `url` |
| `http`         | `method`, `url`, `status`, `contentLength`, `responseTimeMs` |
| `http_echo`    | `endpoint` (`echo`, `respond`, `basic-auth`), `method`, `url`, `status`, `bodySize`, `bodySha256`, `parts`, `cors`; `file` and `error` for respond, `auth` (`ok`, `wrong`, `missing`) for basic-auth. The request body itself is never logged; the `url` holds the whole query, including a respond `body=` |

Examples:
```json
{"timestamp":"2025-07-01T12:00:00.000Z","event":"server_start","url":"http://localhost:7272"}
```

```json
{"timestamp":"2025-07-01T12:00:00.250Z","event":"http","method":"GET","url":"/dist/","status":200,"contentLength":"588","responseTimeMs":3.998}
```

#### Context events — `POST /api/log/context`

Sent by `atest/library/test_app_listener.py` at Robot Framework lifecycle
boundaries:

| `event`      | Additional fields |
|--------------|-------------------|
| `start_suite` | `id`, `name`, `pid` |
| `end_suite`   | `id`, `name`, `pid`, `status` |
| `start_test`  | `id`, `name`, `pid` |
| `end_test`    | `id`, `name`, `pid`, `status` |

`id` follows the Robot Framework structural ID format: `s1`, `s1-s2`, `s1-s2-t3`.

Example:
```json
{"timestamp":"2025-07-01T12:00:00.000Z","event":"start_test","id":"s1-s2-t1","name":"Open Browser","pid":12345}
```

#### Page events — `POST /api/log/event`

Sent by `static/test-app-logger.js` from the browser page via
`navigator.sendBeacon` (XHR fallback).

| `event`      | Additional fields |
|--------------|-------------------|
| `load`       | `url`, `title` |
| `popstate`   | `url`, `title` |
| `click`      | `url`, `tag`, `text` |
| `change`     | `url`, `tag`, `type`, `text`, `value` |
| `submit`     | `url`, `tag`, `id`, `action` |
| `dragstart`  | `url`, `tag`, `text` |
| `drop`       | `url`, `tag`, `text` |
| `hover`      | `url`, `tag`, `text` |

`text` is derived from `aria-label` → `textContent` → `value` → `id` → `name`,
trimmed and capped at 80 characters.

`tag` values are emitted in lowercase (for example `button`, `a`, `input`).

Example:
```json
{"timestamp":"2025-07-01T12:00:01.234Z","event":"click","url":"http://localhost:7272/index.html","tag":"button","text":"Click me"}
```

## HTTP test page and endpoints

`static/http.html` sends one request from the frontend and shows what the
frontend received, so a mocked, aborted or modified request is visible in the
browser. The endpoints below also answer the `HTTP` keyword, which sends its
request with `fetch` from the current page. All of them read the request body
raw, before any body parser, and are binary-safe. They answer CORS by default
(preflight, the request's `Origin`, credentials allowed); `cors=off` in the
query turns that off.

| Endpoint | Behaviour |
|----------|-----------|
| `/api/echo/**` | Any method. Returns JSON with `method`, `url`, `path`, `query`, `headers`, `origin`, `body` (`size`, `sha256`, `contentType`, `text`, `json`, `base64`) and `parts` for `multipart/form-data` in the order sent (`name`, `filename`, `mimeType`, `size`, `sha256`, `text`, `truncated`). A multipart body that cannot be parsed is still echoed, with `parts: null` and `partsError`. `format=html` wraps the JSON in `<pre id="echo">` |
| `/api/respond/**` | The query defines the response: `status`, `statusText`, `contentType`, `header=Name:Value` (repeatable), `delay` (ms), `body`, `file` (a name in `static/http-fixtures/`). Without `body` or `file` it answers with the echo. An invalid `status` (an integer from 200 to 599), `delay`, `statusText` or `header` gets `400` with an `error` naming it |
| `/api/basic-auth/:user/:password` | `401` with `WWW-Authenticate: Basic realm="test-app"` unless the `Authorization` header matches; otherwise the echo plus `authenticatedUser` |

A second origin is the same server reached through `127.0.0.1` instead of
`localhost`.

The page's builder:

| Field (id) | Prefill parameter | Values |
|------------|-------------------|--------|
| `kind` | `kind` | `fetch`, `xhr`, `img`, `form` |
| `method` | `method` | `GET`, `POST`, `PUT`, `PATCH`, `DELETE`, `HEAD`, `OPTIONS` (a form only does `GET`/`POST`) |
| `url` | `url` | request URL |
| `headers` | `headers` | JSON object |
| `body-mode` | `bodyMode` | `none`, `text`, `json`, `form-urlencoded`, `multipart`, `raw-file` |
| `body` | `body` | text; a JSON object of fields for `form-urlencoded`, `multipart` and forms |
| `file`, `fixture` | `fixture` | files for `multipart` and `raw-file`; `fixture` loads one from `http-fixtures/` |
| `file-field` | `fileField` | multipart field name of the files, default `file` |
| `credentials` | `credentials` | fetch `credentials`: `same-origin`, `include`, `omit` |
| `target` | `target` | form target: `form-result` (iframe on the page) or `_self` |

`send=1` sends the request as soon as the page has loaded. A prefill value
that a select does not offer sends nothing; the page shows `#state` `error` and
the value in `#error`. The response panel
shows `#state` (`idle`, `pending`, `done`, `error`), `#status`, `#status-text`,
`#response-url`, `#response-size`, `#response-sha256`, `#response-headers`,
`#response-body`, `#response-image` and `#error`; `#history` lists every
exchange. `#response-body` is the body decoded as UTF-8 exactly as received, or
`[binary: N bytes]`. Only the latest request writes the panel; an earlier one that
answers later only adds its history entry. An `<img>` load and a form submit
cannot read the status, size or headers, so for them only the body (image size,
or the form result) is shown. A form submit that ends on the browser's error page
is an `error`; one that never loads counts as an `error` after 15 seconds. The
page cannot tell the browser's error page from a page on another origin, so a
same-origin form submit that a redirect takes to another origin is an `error`
too. Test cross-origin redirects with `fetch`, where `#response-url` shows the
final URL.

`static/http-fixtures/SHA256SUMS` lists the checksums of the fixtures. The
helpers in `atest/library/http_test_page.py` build prefilled page URLs and
return fixture paths and checksums.

## Adding a new test page

1. Create the `.html` file under `static/`.
2. Add `<script src="/test-app-logger.js"></script>` before `</body>` (or
   before `</html>` if the file has no `<body>` element).

## Building

```bash
inv create-test-app
```

This compiles `src/server.ts` → `dist/server.js` via esbuild.
